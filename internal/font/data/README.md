# Embedded CMap data

`cmap.bin` is generated by `scripts/gen_cmaps.py` from the Adobe CMap
resources in `poppler-data` 0.4.12-1. The source files are usually installed
under `/usr/share/poppler/cMap/` with one subdirectory per collection.

Included CMaps:

| Collection | CMaps | Adobe version |
| --- | --- | --- |
| Adobe-GB1 | `UniGB-UCS2-H/V`, `UniGB-UTF16-H/V`, `GBK-EUC-H/V`, `GB-EUC-H/V` | 1.007–12.006 |
| Adobe-CNS1 | `UniCNS-UCS2-H/V`, `UniCNS-UTF16-H/V`, `B5-H/V`, `B5pc-H/V`, `ETen-B5-H/V`, `ETenms-B5-H/V` | 1.009–12.006 |
| Adobe-Japan1 | `UniJIS-UCS2-H/V`, `UniJIS-UTF16-H/V`, `90ms-RKSJ-H/V`, `90msp-RKSJ-H/V`, `90pv-RKSJ-H/V`, `EUC-H/V`, `H/V` | 1.027–12.006 |
| Adobe-Korea1 | `UniKS-UCS2-H/V`, `UniKS-UTF16-H/V`, `KSCms-UHC-H/V`, `KSCms-UHC-HW-H/V`, `KSC-EUC-H/V`, `KSCpc-EUC-H/V`, `KSC-Johab-H/V` | 1.008–10.006 |

The binary stores code-space ranges, code-to-CID ranges, notdef ranges, and
code-to-Unicode ranges. Unicode CMaps derive Unicode directly from the
character code; legacy encodings use a code-keyed or CID-keyed `*-UCS2` table
(including inherited `usecmap` data). A base character followed only by
variation selectors is reduced to the base character. Other multi-character
destinations (1,878 entries in the current source data) are omitted because
the one-rune table cannot represent them; common CJK text is unaffected.

Regenerate after changing the source data or the generator:

```bash
POPPLER_CMAP_DIR=/usr/share/poppler/cMap scripts/gen_cmaps.py
```

Do not edit `cmap.bin` by hand. The Adobe copyright and redistribution terms
are in `CMAP-LICENSE.txt` and are also recorded in `THIRD_PARTY.md`.
